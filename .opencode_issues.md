# Working bug list (temporary, delete when done)

## Candidate A — online_softmax per-batch sink + query tiling
- online_softmax.py: query_chunk path normalizes sink_logits against a
  synthetic B=1 probe, so `[B, 1]` / `[B, 1, 1]` sinks are rejected (or
  mistaken for `[H, 1]`) whenever B > 1 and B != H. The untitled path
  accepts them.
- Repro: `online_softmax_attention(q[2,4,6,8], k, v, query_chunk=3,
  sink_logits=torch.randn(2,1))` -> ValueError.

## Candidate B — exact_test_resolution overflow at tiny p floors
- multi_seed_stats.py: for n_eff beyond the normal float range the p floor
  is subnormal and `alpha / p_min` overflows; `int(math.floor(inf))` raises.
  A large `family_size` times the tiny floor also raises in int->float
  conversion. Both quantities remain well-defined (huge family count / 1.0).
- Repro: `exact_test_resolution(1030)` and with family_size=10**400.

## Candidate C — exact-test minimum-n rounds an exact boundary up
- multi_seed_stats._min_effective used log/ceil, so cases where
  family*sided/2**n == alpha exactly (e.g. alpha=0.5, family=2, n=3)
  computed 3.0000000000000004 and returned n=4. The budget was overstated
  by one. Use exact rational comparisons against the float alpha.

## Candidate D — curve slope aborts on finite extremes
- results_analysis._tail_slope: math.fsum raises OverflowError on an
  intermediate partial sum for mixed finite extremes (e.g.
  [1.5, 1e-308, ..., -1e308, 1e308, ...]), even though the scaled slope is
  representable. The existing finite/extreme fallback never ran because the
  exception escaped before the isfinite check.

## Candidate E — validation gap becomes -inf for finite losses
- train_diagnostics.ValidationCurve.finalize: ten finite 1e308 training
  losses make sum(tail)=inf, so the reported generalization_gap is -inf
  and the record fails strict JSON. Use the existing overflow-safe mean and
  report None if the true gap is unrepresentable.

## Candidate F — timing summaries overflow on finite extremes
- timing_stats.summarize_timings_ms: raw sum/median/stdev overflow for
  finite values near the float limit (e.g. [1e308, 1e308] -> inf mean,
  [0, 1e308] -> NaN bootstrap CI from (a+b)/2). ratio_of_medians_ci could
  emit inf ratios. Use overflow-safe mean/median/std and skip
  unrepresentable ratios.

## Candidate G — sign_test overflows above 1023 informative pairs
- multi_seed_stats.sign_test evaluated 2*tail/float(2**n_eff); the float
  conversion raises OverflowError for n_eff >= 1024. Evaluate the same
  ratio in log space above that boundary (the exact-resolution helper
  already had the analogous branch).

## Candidate H — validation regret becomes +inf for finite endpoints
- train_diagnostics.ValidationCurve.finalize: final_loss - best_loss can
  overflow when the endpoints are finite (-1e308 -> +1e308). Both the
  top-level and the early-stopping-summary regret were emitted as +inf.
  Report None when unrepresentable.
